# Использованные промпты

Список промптов, использованных при создании и доработке LangChain-агента. Промпты приведены в хронологическом порядке и оформлены как итеративные изменения проекта.

---

## Промпт 1 — Исходное задание (создание агента)

**Цель:** собрать и запустить минимального AI-агента на LangChain, который выступает в роли натурально-языковой обёртки над API.

```text
Минимальный агент на LangChain

Цель: собрать и запустить минимального AI-агента на LangChain, который выступает
в роли натурально-языковой обёртки над API.

Агент должен:
- принимать запрос пользователя на естественном языке;
- интерпретировать намерение пользователя;
- вызывать один или несколько API-методов через tool;
- возвращать структурированный результат с указанием статуса выполнения.

Что нужно сделать:
1. Подготовить окружение: минимальный проект, зафиксировать зависимости
   (requirements.txt / pyproject.toml).
2. Выбрать LLM-провайдера (облачный или локальный). Секреты не коммитить,
   добавить .env.example и описание настройки.
3. Определить API-домен (mock API / публичное тестовое / внутренний /
   минимальный API в этом же репозитории). Достаточно 2–4 операций:
   создать сущность, получить сущность, обновить состояние, получить список/статистику.
4. Реализовать tool для вызова API: оформить как LangChain tool, внутри —
   явный HTTP-вызов или функция-обёртка, возвращающая структурированный
   результат (JSON / dict → string).
5. Собрать агента: системный prompt (роль API-оператора, ограничения, правила
   вызова tool), подключить API-tool, запуск из CLI:
   python main.py "создай пользователя с именем Alex"
6. Определить контракт ответа в фиксированном формате:
   Status: success | error
   Action: <описание действия>
   Data: <результат API>
   Errors: <если есть>
7. Проверка: минимум 5 разных пользовательских запросов, из них минимум 3 —
   с реальным вызовом API-tool. Зафиксировать запросы и ответы.
8. Сохранить все используемые промпты в Markdown (системный prompt и
   пользовательские шаблоны).
```

**Ожидаемый результат:** рабочий каркас проекта — LangChain-агент с системным промптом, API-tool с реальным вызовом, CLI-запуск и фиксированный контракт ответа.

## Промпт 2 — Смена LLM-провайдера на Ollama

**Цель:** перейти с облачной модели Claude на локальную через Ollama.

```text
замени использование claude на ollama, модель qwen3.5:9b
```

**Ожидаемый результат:** инициализация LLM через `ChatOllama` (или совместимый класс LangChain) с моделью `qwen3.5:9b`, обновление зависимостей и `.env.example` под локального провайдера.

## Промпт 3 — Добавление хранилища данных SQLite

**Цель:** заменить in-memory / mock-хранилище на полноценную БД и подготовить схему.

```text
добавь sqlite как основное хранилище данных, инициализируй структуру таблиц
```

**Ожидаемый результат:** подключение SQLite, создание модуля инициализации БД (`CREATE TABLE ...`), автоматическое создание таблиц при первом запуске, переключение API-операций на чтение/запись из базы.

## Промпт 4 — Добавление прокси-tool к LLM

**Цель:** дать агенту инструмент-«заглушку» для произвольных запросов, не покрытых другими tool'ами.

```text
добавь еще один tool, который проксирует любой другой запрос через агента к LLM и вернет кастомный ответ
```

**Ожидаемый результат:** новый LangChain tool, который принимает свободный текстовый запрос, передаёт его в LLM и возвращает кастомный (структурированный) ответ; используется как fallback для запросов вне основного API-домена.
